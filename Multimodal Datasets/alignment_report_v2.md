# Multimodal Alignment Report V2

Generated by `multimodal_alignment_v2.py` (multimodal_alignment_v2.0.0). Every number below is computed in this run. The result is **second-level temporal alignment** of two sensors inside one capture. It does **not** establish packet-to-UE or flow-to-UE correspondence: no shared packet identifier or UE-to-flow mapping exists, and several UEs are pooled into one radio window.

## 10. Radio byte counters are not part of this join

A byte-counter delta covers the interval `(previous timestamp_ms, timestamp_ms]`. The radio window table attributes it to the second containing the *end* of that interval (`timestamp_s`). That end-second label does **not** show that the delta belongs entirely to that one-second network window `[t, t+1)`: the interval is about one second long and starts at the previous sample's millisecond phase, so it normally overlaps two consecutive network windows.

Measured on 4,554 radio windows that have a valid delta: the interval begins in the previous second in 100.0% of them; the fraction of the interval lying inside the end second has min 0.028, 5th percentile 0.029, median 0.522, 95th percentile 0.932, max 0.989. With several UEs the window combines intervals with different phases, so the union is slightly longer than one second.

No allocation method is invented here. `dlBytes_delta_sum`, `ulBytes_delta_sum` and the interval bounds remain in `radio_window_features_v2.csv` / `radio_counter_diagnostics_v2.csv` for a future sensitivity experiment that first fixes an interval-allocation rule. They are excluded from `multimodal_dataset_v2.csv`.

## 11. Limitations

1. Temporal co-occurrence at 1-second resolution only. There is no packet ID or UE-to-flow mapping; several UEs are pooled per radio window. No packet-to-UE correspondence is claimed.
2. The two sensors may have a residual clock skew of a few seconds that cannot be resolved from these files; no correction and no fuzzy matching were applied. The start/end offsets in section 7 differ per scenario.
3. Missing network windows are seconds without a captured packet; their relation to UE activity is unknown (section 8.3).
4. Inner-join retention differs by scenario (section 7); unmatched rows are reported, never repaired.
5. Timezone agreement validates Member 1's conversion against Europe/Dublin rules; it does not prove logger/capture clock synchronisation.
6. The radio feature columns inherit the open questions listed in `radio_quality_report_v2.md` (scenario/session dependence, held-out KPI semantics, treatment of all-zero UL reports).
7. Class and capture date are confounded in the source captures, so scenario-level evaluation splits and a radio-only baseline are still needed before any detection claim.
8. The raw packet and radio source files are not in the repository, so none of the above could be checked at source.
